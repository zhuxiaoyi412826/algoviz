🔴 红黑树
自平衡二叉搜索树，通过颜色标记和旋转操作保持平衡，保证最坏情况下 O(log n) 的查找、插入、删除。
查找/插入/删除: O(log n) 空间: O(n)
点击展开详情

五条性质

  • 每个节点是红色或黑色
  • 根节点是黑色
  • 每个叶子节点(NIL)是黑色
  • 红色节点的子节点必须是黑色（不能有连续红节点）
  • 从任一节点到其所有叶子节点的路径包含相同数量的黑色节点

核心操作

  • 左旋/右旋：调整树结构，不破坏 BST 性质
  • 插入调整：变色 + 旋转，保证红黑性质
  • 删除调整：更复杂，需处理双黑节点

应用场景

  • Java TreeMap / TreeSet 的底层实现
  • C++ std::map / std::set 的底层实现
  • Linux 内核进程调度 (CFS)

示例：左旋操作

void leftRotate(Node *x) { Node *y = x->right; // y 为 x 的右子 x->right = y->left; // y 的左子挂到 x 右侧 if (y->left != NIL) y->left->parent = x; y->parent = x->parent; // y 接替 x 的位置 if (x->parent == NIL) root = y; else if (x == x->parent->left) x->parent->left = y; else x->parent->right = y; y->left = x; // x 成为 y 的左子 x->parent = y; }
🌿 B+树
多路平衡搜索树，所有数据存储在叶子节点，叶子节点通过链表连接，是数据库索引的首选结构。
查找/插入/删除: O(log n) 空间: O(n)
点击展开详情

与 B 树的区别

  • 所有数据只在叶子节点，内部节点仅存索引
  • 叶子节点通过双向链表连接，支持范围查询
  • 内部节点更多 → 树更矮 → 磁盘 I/O 更少

核心特性

  • 每个节点最多 m 个子节点（m 阶 B+树）
  • 每个非根节点至少 ⌈m/2⌉ 个子节点
  • 所有叶子节点在同一层

应用场景

  • MySQL InnoDB 索引结构
  • 文件系统目录索引
  • 数据库范围查询优化

示例：B+树节点结构

class BPlusNode { boolean isLeaf; // 是否为叶子节点 int[] keys; // 关键字数组 BPlusNode[] children; // 内部节点的子节点指针 BPlusNode next; // 叶子节点的后继指针(链表) Object[] data; // 叶子节点存储的数据 int keyCount; // 当前关键字数量 }
🔗 并查集
用于管理不相交集合的数据结构，支持高效合并集合和查找元素所属集合，配合路径压缩近乎 O(1)。
查找/合并: O(α(n)) ≈ O(1) 空间: O(n)
点击展开详情

两种优化

  • 路径压缩：查找时将路径上的节点直接指向根
  • 按秩合并：小树挂到大树下，保持平衡

应用场景

  • Kruskal 最小生成树算法中的环检测
  • 网络连通性问题
  • 社交网络好友分组
  • 等价关系判定

示例：带路径压缩和按秩合并

int[] parent = new int[n]; int[] rank = new int[n]; int find(int x) { if (parent[x] != x) parent[x] = find(parent[x]); // 路径压缩 return parent[x]; } void union(int x, int y) { int px = find(x), py = find(y); if (px == py) return; if (rank[px] < rank[py]) { // 按秩合并 parent[px] = py; } else if (rank[px] > rank[py]) { parent[py] = px; } else { parent[py] = px; rank[px]++; } }
🔲 四叉树
将二维空间递归划分为四个象限的树结构，广泛用于空间分区、图像处理和碰撞检测。
查找/插入: O(log n) 空间: O(n)
点击展开详情

结构原理

  • 每个节点将空间分成 NW、NE、SW、SE 四个子区域
  • 当子区域内对象超过阈值时继续分裂
  • 叶子节点存储实际数据（点、矩形等）

应用场景

  • 2D 游戏碰撞检测（如 Bullet 引擎）
  • 图像压缩（同色区域合并）
  • 地理信息系统 (GIS) 空间查询
  • 粒子系统空间分区

示例：四叉树节点

class QuadTreeNode { int x, y, width, height; // 区域边界 QuadTreeNode[] children; // 4个子节点 NW,NE,SW,SE List<Point> points; // 存储的点 int capacity; // 分裂阈值 boolean isDivided; void insert(Point p) { if (points.size() < capacity) { points.add(p); } else { if (!isDivided) subdivide(); // 插入到对应子象限 for (QuadTreeNode child : children) if (child.contains(p)) child.insert(p); } } }
📊 树状数组 (BIT)
利用二进制索引实现的前缀和数据结构，支持 O(log n) 的单点更新和区间求和，代码极其简洁。
更新/查询: O(log n) 空间: O(n)
点击展开详情

核心思想：lowbit

  • lowbit(x) = x & (-x)：取 x 最低位的 1
  • 每个节点 tree[i] 管辖范围：[i - lowbit(i) + 1, i]
  • 前缀和 = 沿 lowbit 跳跃求和

与线段树对比

  • 优点：代码极短，常数小，1D 场景首选
  • 缺点：只能做前缀类操作，不能区间更新（线段树可以）

应用场景

  • 逆序对计数
  • 动态前缀和
  • 二维矩阵子矩阵求和

示例：单点更新 + 前缀查询

int[] tree = new int[n + 1]; int lowbit(int x) { return x & (-x); } void update(int i, int delta) { // 单点更新 for (; i <= n; i += lowbit(i)) tree[i] += delta; } int query(int i) { // 前缀和 [1, i] int sum = 0; for (; i > 0; i -= lowbit(i)) sum += tree[i]; return sum; } // 区间和 [l, r] = query(r) - query(l - 1)
🌸 Bloom Filter
空间效率极高的概率型数据结构，用于判断元素是否在集合中，可能有误判但不会漏判。
插入/查询: O(k) 空间: O(m) bits
点击展开详情

工作原理

  • 一个 m 位的位数组，初始全为 0
  • k 个独立的哈希函数
  • 插入：对元素做 k 次哈希，对应位置 1
  • 查询：若 k 个位置全为 1 → 可能在集合中；任一为 0 → 一定不在

特性

  • 假阳性：可能误判存在（可接受）
  • 无假阴性：说不在就一定不在
  • 不支持删除（可用 Counting Bloom Filter 解决）

应用场景

  • 缓存穿透防护（Redis 前置过滤）
  • 垃圾邮件/URL 过滤
  • 数据库 HBase/LevelDB 读过滤
  • 爬虫 URL 去重

示例：Bloom Filter 实现

class BloomFilter { BitSet bits = new BitSet(m); // m 位数组 int k; // 哈希函数个数 void add(String item) { for (int i = 0; i < k; i++) { int hash = hash(item, i) % m; bits.set(hash); } } boolean mightContain(String item) { for (int i = 0; i < k; i++) { int hash = hash(item, i) % m; if (!bits.get(hash)) return false; // 一定不在 } return true; // 可能在 } }
🔠 Trie 字典树
前缀树，将字符串按字符分解存储在树中，高效支持前缀搜索、自动补全和词频统计。
插入/查找: O(L) 空间: O(N×L)
点击展开详情

结构特点

  • 根节点为空，每个边代表一个字符
  • 从根到某节点的路径构成一个字符串前缀
  • 标记结束节点表示一个完整单词
  • 公共前缀共享路径，节省空间

应用场景

  • 搜索引擎自动补全/联想
  • 拼写检查与纠错
  • IP 路由表最长前缀匹配
  • 敏感词过滤系统

示例：Trie 插入与查找

class TrieNode { TrieNode[] children = new TrieNode[26]; boolean isEnd; } class Trie { TrieNode root = new TrieNode(); void insert(String word) { TrieNode node = root; for (char c : word.toCharArray()) { int idx = c - 'a'; if (node.children[idx] == null) node.children[idx] = new TrieNode(); node = node.children[idx]; } node.isEnd = true; } boolean search(String word) { TrieNode node = root; for (char c : word.toCharArray()) { int idx = c - 'a'; if (node.children[idx] == null) return false; node = node.children[idx]; } return node.isEnd; } }
📉 斐波那契堆
支持 O(1) 插入和合并操作的优先队列，理论上比二叉堆更优，是 Dijkstra 算法的最佳配套结构。
插入/合并: O(1), 删除最小: O(log n) 空间: O(n)
点击展开详情

与二叉堆对比

  • 插入：O(1) vs 二叉堆 O(log n)
  • 合并：O(1) vs 二叉堆 O(n)
  • 删除最小：均摊 O(log n)，但常数较大
  • 减小键值：O(1) 均摊（Dijkstra 关键优化）

核心思想

  • 由一组最小堆有序树组成的森林
  • 延迟合并策略：先标记，后续统一级联切除
  • 节点度数服从斐波那契数列 → 得名

应用场景

  • Dijkstra 最短路径算法（O(E + V log V)）
  • Prim 最小生成树算法
  • 理论分析中的渐进最优优先队列

示例：斐波那契堆节点结构

class FibNode { int key; // 节点值 int degree; // 度数(子节点个数) boolean marked; // 是否被标记(曾失去子节点) FibNode parent; FibNode child; // 任意一个子节点 FibNode left, right; // 双向链表兄弟指针 }
✖️ 十字链表
稀疏矩阵的高效存储结构，每个非零元素同时处于行链表和列链表中，支持快速行列遍历。
访问: O(行/列长度) 空间: O(非零元素数)
点击展开详情

结构原理

  • 每个非零元素用一个节点存储：row, col, value
  • 两个指针：right（同行下一个）、down（同列下一个）
  • 行头指针数组 + 列头指针数组
  • 相比三元组法，支持高效插入/删除

与邻接表/三元组对比

  • 三元组：简单但不支持高效修改
  • 邻接表：只适合行遍历，列遍历困难
  • 十字链表：行列双向遍历，最适合动态稀疏矩阵

应用场景

  • 稀疏矩阵运算（加法、乘法、转置）
  • 有限元素分析 (FEA) 中的刚度矩阵
  • 图的有向图邻接存储（行=出边，列=入边）

示例：十字链表节点

class OLNode { int row, col; // 行号、列号 double value; // 非零元素值 OLNode right; // 同行下一个非零元素 OLNode down; // 同列下一个非零元素 } class CrossList { OLNode[] rhead; // 行头指针数组 OLNode[] chead; // 列头指针数组 int rows, cols; // 矩阵行列数 }
